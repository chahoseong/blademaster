# ROADMAP.md

이 문서는 프로젝트의 목표, 범위, 완료 기준과 현재 계획을 공유한다.

- 진행 계획은 현재 정보에 기반하며, 새로운 정보와 작업 결과에 따라 재검토한다.
- 단계의 결과가 후속 계획의 전제를 바꾸면, 다음 단계에 앞서 변경과 이유를 제안한다.
- 합의된 목표·범위·필수 제약의 변경은 사용자와 논의한다. 개별 작업과 구현 방법은 이슈에서 정의한다.

## 프로젝트 목표(Project Objective)

게임플레이 프로그래머 채용에 제출할 포트폴리오를 만든다. **자세(Posture)를 겨루는 근접 전투 한 판**이 처음부터 끝까지 성립하고, 그 전투를 이루는 결정과 계산을 직접 설명하고 응용할 수 있는 상태에 도달한다.

이 프로젝트의 또 다른 목적은 **설계 대안을 비교하고 선택 근거를 설명하는 능력**, 그리고 **액션 RPG 메커니즘의 원리를 이해해 다른 구현에 응용하는 능력**을 기르는 것이다. GAS·애니메이션·판정은 이 하나의 주제를 구현하는 수단이다.

## 범위(Scope)

### 포함(In Scope)

- 자세 공방의 순환 — 공격·콤보, 가드·패링·회피, 자세 소모·회복·붕괴, 공격 타입(일반·방어불가)과 텔레그래프
- 순환을 검증할 상대 — 가드를 수행하는 적 1종과 2페이즈 보스 1체, 전투가 성립하는 아레나 하나
- 전투 상태를 읽을 수 있는 최소 피드백 — 히트스톱, 카메라 반응, 체력·자세 게이지, 결과를 구분할 만큼의 VFX·SFX
- 공격을 데이터로 추가하는 경로와 디버그 가시화

### 제외(Out of Scope)

- 멀티플레이 — 협동·대전, 리플리케이션, 예측, 지연 보상, 리슨 서버, 전용 서버는 모두 범위 밖이다
- 난이도와 재미의 적정성 검증 — 외부 플레이테스트를 하지 않는다
- 최소 피드백을 넘는 연출 완성도
- 치명타 — 붕괴의 대가는 무방비 구간으로 둔다. 붕괴한 상대에게만 성립하는 별도 공격도, 붕괴 중 피해 배율도 만들지 않는다
- 적 종류 확대와, 새로운 행동 방식을 데이터로 만드는 적 프레임워크
- 무기 다양화·스태미나·방향 스탠스, 레벨 진행·세이브, 상용 수준의 최적화와 스토어 배포

## 완료 기준(Success Criteria)

- 보스 한 판이 시작·승리·패배·재시도까지 규칙대로 끝난다 — 근거: 플레이 영상 1편
- 현재 공격 모델로 표현되는 새 공격 1개를 C++ 수정 없이 추가할 수 있다 — 새로운 실행 규칙이 필요한 공격은 코드 추가가 정상이다. 확인: 추가 시 변경 파일이 데이터·애셋뿐
- 기존 전투 행동의 조합과 수치로 정의되는 적 변형을 C++ 수정 없이 추가할 수 있다 — 새로운 행동 방식이 필요한 적은 코드 추가가 정상이다
- 한 번의 교환을 입력 → 어빌리티 → 판정 → GameplayEffect → 어트리뷰트 → 붕괴 → 피드백까지 따라가며, 각 단계에서 **무엇을 어떻게 계산해 결정하는지**와 그 결정을 **어느 시스템이 소유하는지** 설명할 수 있다 — 근거: 아키텍처 다이어그램과, 락온 후보 판정(카메라 전방과 대상 방향의 각도, 가림 검사)·칼 궤적 판정(점 샘플과 substep)·자세 회복(체력 연동) 같은 핵심 계산을 담은 기술 문서

## 진행 계획(Phases)

| 단계 | 목표 | 완료 기준 | 상태 |
| :-: | :-: | :-: | :-: |
| Phase 1: 기반 | 캐릭터·카메라·락온과 GAS 토대가 동작한다 | 락온 상태의 이동·카메라가 어색하지 않고, 어트리뷰트가 GameplayEffect로만 변한다 · 근거: 이슈 #1~#6 | 완료 |
| Phase 2: 공격 | 데이터로 정의한 공격이 히트 판정으로 적중하고 피해·피격 반응까지 이어진다 | 새 공격 1개를 `Source/` 변경 없이 추가한다 · 근거: 이슈 #8~#15, 4타 추가 커밋 | 완료 |
| Phase 3: 핵심 전투 루프 | 공격 → 가드·패링·회피 → 체력 또는 자세 → 붕괴 → 회복으로 돌아오는 순환이 플레이어와 적 양쪽에서 닫힌다 | 자세가 `Specs/001-posture.md`와 `Specs/002-stagger.md` 규칙대로 소모·회복·붕괴한다 · 검증 장치로 더미에게 공격을 지시해 가드에서 붕괴까지를 양방향으로 재현한다 · 방어불가 공격은 가드로 막히지 않고 회피를 요구한다 | 진행 중 |
| Phase 4: 검증용 적 | AI가 이 순환의 기존 행동을 선택해 실제 공방을 만든다 | 적이 공격과 가드를 상황에 따라 선택하고, 그 선택이 플레이어의 대응(자세를 깎아 붕괴시키기, 회피)을 바꾼다 · 기존 행동의 조합으로 적 변형 하나를 데이터만으로 추가한다 · 근거: 전투 영상과 전투 로그 | 예정 |
| Phase 5: 최소 게임필 | 전투의 상태가 사람이 읽을 수 있게 드러난다 | 소리를 끈 영상에서 타격·가드·패링·붕괴가 구분된다 · 소리를 켜면 각 결과에 대응하는 최소한의 오디오가 있다 · 연출이 기존 타격 알림 지점에만 붙어 전투 규칙을 바꾸지 않는다 | 예정 |
| Phase 6: 보스 검증 | 더 복잡한 전투에서도 순환이 그대로 확장된다 | 2페이즈 보스의 모든 패턴에 대응 수단(가드·패링·회피)이 있다 · 2페이즈의 신규 행동을 기존 전투 규칙(자세·판정·피해)을 고치지 않고 더할 수 있다 · 시작·승리·패배·재시도가 규칙대로 돈다 | 예정 |
| Phase 7: 최종 검증·포트폴리오 정리 | 에디터 밖에서도 동작하고, 코드를 열지 않고도 시스템을 이해할 수 있다 | Windows 패키지 빌드(Development)에서 보스전을 시작부터 승패·재시도까지 한 번 완주한다 · 영상 2종(일반·디버그), 아키텍처 다이어그램, "새 공격/적 변형 추가" 절차, README가 갖춰진다 · 근거: 그 절차만 따라 하나를 추가해 본 기록 | 예정 |
