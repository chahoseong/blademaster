# 로드맵

## 시간 예산

- 평일 최대 2h × 5 + 주말 최대 4h × 2 = **주 18h 상한**
- 현실 가동률 감안 **주 12~14h**로 계획
- 총 **148h ≈ 11주 (약 3개월)**

마일스톤은 주차가 아니라 **시간**으로 관리한다. 한 주 못 하는 일은 생기지만 시간 총량은 어긋나지 않는다.

각 마일스톤에는 **검증 기준**이 있다. 기준을 통과하지 못하면 다음으로 넘어가지 않는다.

---

## M0 — 기반 (8h)

GAS 경험이 있으므로 셋업 위주로 짧게 끊는다.

- [ ] **선행: SnSAnimsetPro 애니메이션 재고 조사** — 필요한 목록이 실제로 있는지 확인
      (공격 3타 / 가드 / 가드 피격 / 4방향 회피 / 피격 반응 / 자세 붕괴 / 치명타 피격·가해 / 사망)
      → 없는 것이 있으면 이 시점에 설계를 조정한다. **나중에 발견하면 손해가 크다.**
- [ ] GameplayAbilities 플러그인 활성화, `Blademaster.Build.cs`에 모듈 추가
- [ ] 캐릭터 이동, 스프링암 카메라, EnhancedInput 매핑 (게임패드 우선 / KBM 병행)
- [ ] `ASC` + `AttributeSet` (Health, MaxHealth, Posture, MaxPosture, PostureRegenRate)
- [ ] `UBMTargetingComponent` — 락온

**검증:** 락온 상태의 이동·카메라가 어색하지 않고, 어트리뷰트가 GameplayEffect를 통해서만 변경된다.

## M1 — 공격 (25h) · 누적 33h

- [ ] `UBMAttackDefinition` 데이터 에셋
- [ ] 공격 GameplayAbility (몽타주 재생 + 데이터 참조)
- [ ] `UAnimNotifyState_HitWindow` — 서버에서만 오버랩 판정, 히트 대상 중복 제거
- [ ] HP / 자세 데미지 GameplayEffect 적용
- [ ] 콤보 체인 + `UAnimNotifyState_ComboWindow` (캔슬 윈도우)
- [ ] **디버그 뷰** (`bm.Debug.Hitbox`, `bm.Debug.Combat`)

**검증:** 새 공격 1개를 **C++ 수정 없이** 데이터 에셋 + 몽타주 + 노티파이만으로 추가할 수 있다.

## M2 — 방어 (25h) · 누적 58h

- [ ] 가드 (홀드) — 자세 축적, 방어불가 공격에는 무효
- [ ] 저스트 가드 — 프레임 윈도우 판정, 성공 시 적 자세 역데미지, **실패 시 일반 가드로 폴백**
- [ ] 회피 — `UAnimNotifyState_Invulnerable` 무적 구간 + 자세 소폭 소모
- [ ] 자세 자연 회복 (HP 잔량 연동), 최대치 도달 시 붕괴(Stagger) 상태
- [ ] 치명타 어빌리티 (양방향 — 플레이어도 당한다)
- [ ] 공격 타입 시스템 (일반 / 방어불가) + 텔레그래프 표시
- [ ] **PIE 리슨 서버 2인 검증 1회**

**검증:** 자세 붕괴 → 치명타 루프가 플레이어·적 **양방향**으로 동작한다.
이 시점에서 이미 "혼자 허수아비를 상대로 노는 것"이 재미있어야 한다. 아니면 튜닝하고 넘어간다.

---

## M3 — 적 AI (30h) · 누적 88h

- [ ] 행동 트리 + 블랙보드, 접근 / 간격 유지 / 배회
- [ ] `UBMEnemyDefinition` 기반 공격 선택 (가중치)
- [ ] 텔레그래프 (선딜 + 공격 타입 인디케이터)
- [ ] 적의 방어 행동 (잡몹 A는 가드 수행)
- [ ] **잡몹 A "리듬 교사"** — 느린 3타, 방어불가 없음, 가드함
- [ ] **잡몹 B "방어불가 전문"** — 방어불가 섞음, 짧은 선딜, 가드 안 함

**검증:**
1. 새 적 1종을 데이터 에셋 + 애님 조합으로 추가할 수 있다.
2. **3분 이상 싸워도 지루하지 않다.** ← 여기서 실패하면 M4로 넘어가지 말 것.

> **이 시점의 산출물을 영상으로 남긴다.** 프로젝트가 어디서 멈추더라도
> "완결된 전투"를 보여줄 수 있는 첫 지점이다.

## M4 — 게임필 (20h) · 누적 108h

기반이 다 선 다음에 몰아서 한다. 초반에 손대면 시스템이 바뀔 때마다 재튜닝이라 순수 낭비.

- [ ] 히트스톱 (히트 타입별 정지 길이 차등)
- [ ] 카메라 셰이크 / 히트 리액션 방향성
- [ ] VFX / SFX 타이밍 (특히 저스트 가드 성공 피드백)
- [ ] UI — 플레이어 및 락온 대상의 HP·자세 게이지
- [ ] 치명타 연출 (카메라 컷)

**검증:** 소리를 끄고 영상만 봐도 타격이 "닿는" 느낌이 난다.

**검증:** 처음 하는 사람이 3~5회 시도로 클리어한다. 너무 쉬워도 너무 어려워도 실패.

## 진행 원칙

1. **마일스톤 검증 기준을 통과하지 못하면 다음으로 가지 않는다.**
   미완성 기능을 쌓아두는 것이 이런 프로젝트가 실패하는 가장 흔한 경로다.
2. **M3 종료 시점에 영상을 남긴다.** 중간 산출물이 있어야 프로젝트가 멈춰도 손해가 없다.
3. **디버그 가시화는 M1에 만든다.** 마지막에 만들면 이미 못 쓴다.
4. 확장 아이디어(방향 스탠스, 스태미나, 무기 다양화)는 **전부 M5 이후**로 미룬다.
   코어가 재미있어지기 전에 넓히면 아무것도 깊어지지 않는다.
